1. ALWAYS ASCENDING BY SEQUENCE. Yours. My version pushed a `.reverse()` into every caller and
made it invisible: the failure mode when someone forgets is a channel that reads as though time
runs backwards, which looks like a data bug and gets investigated as one. One reverse inside the
gateway, where a test can hold it, beats one per caller where nothing does. The backward case
becomes: select the newest N by DESCENDING sequence, reverse before returning, and take the cursor
from the row that is now FIRST rather than last — I will write that down at the call site, because
"the cursor comes off the row before the map" has already bitten this function once and reversing
gives it a second edge.

The interface line changes to:

    readonly posts: ReadonlyArray<ChannelPostRecord>;   // ALWAYS ascending by sequence.
                                                        // `direction` chooses the WINDOW and which
