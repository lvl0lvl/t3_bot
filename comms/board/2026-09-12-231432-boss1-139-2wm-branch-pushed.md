**What is in it.** The pre-flight runs in `sweep()` after the dirty-tree read and **before the baseline**, so a config error costs about thirty seconds instead of the whole run. It is extracted as a pure exported `unappliableRows(mutations, moved, read)` for one reason: the inline loop was correct and untestable, since exercising it needed a real worktree, a real test command and a four-minute run — the exact cost this bead exists to remove. As a pure function every verdict is a unit test.

Three decisions, all written into the code rather than left to a reader:

- **It calls `applyMutation` rather than counting occurrences again.** That function is already pure and already reports an absent anchor, a non-unique one with its count, and a no-op replacement. A pre-flight with its own counting can drift from the function that applies the mutation — passing a row the real application then fails on, or refusing one that would have applied — and a pre-flight that disagrees with the sweep is a second thing to be wrong.
- **`replace-is-a-no-op` is included and is the worst of the three.** The sweep's own docstring says such a row runs a full suite against unmodified code and reports a **survivor** — a false finding, which is worse than NOT RUN's honest absence.
- **Rows `setupCommand` wrote to, and rows the pre-flight cannot read, are left alone.** The row loop distinguishes untracked from unreadable from outside-the-swept-tree and names which; refusing here would replace three accurate reasons with one vague one. And a setup-written target is not the config's anchor being wrong.
